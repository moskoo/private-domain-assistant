# 企业微信与全链路 SOP

用于原生功能方案、跨角色交接、SCRM 配置蓝图和自动化需求。先说明能手动执行的流程，再判断哪些节点适合工具辅助。

## 核对现状与能力

确认个人微信或企业微信、账号与角色权限、客户规模、当前管理方式、现有工具，以及客户与订单如何对应。不给未查看的后台编造配置路径或运行状态。

对需要的能力记录“原生可用 / 现有工具可用 / 需人工 / 待核验”，例如渠道来源、欢迎语、标签、群发任务、任务执行结果、订单回写、员工转接。没有工具不阻塞内容和人工流程交付。

涉及具体配置时核验当期官方文档和账号实际可见能力。频控要区分任务创建、员工发送、单个客户可接收条数与展示；个人操作、企业任务、群消息、朋友圈不能共用一个数字。经营建议的触达频率与平台限制分别标明。

## 全链路与状态

入口获客 → 接待建档 → 提供价值 → 确认需求与成交 → 履约服务 → 合适时的复购或推荐。

不要求每个人都经过群或每一步按固定天数完成。阶段以行为与服务事实变化：正在比较、已购待交付、使用中、有服务问题、可复购、暂停营销等。

SOP 表建议字段：

| 对象/当前状态 | 触发条件 | 排除条件 | 动作与素材 | 时机/频控 | 责任与交接 | 完成证据 | 退出/升级 |
|---|---|---|---|---|---|---|---|

表格太宽时拆成“规则表”和“素材表”，用动作 ID 关联。

## 新联系的承接示例

以下是需按营业时间、人力和客户承诺调整的示例：

- 接待时：确认来源与请求，清楚自我介绍，交付承诺资料或服务。
- 首次沟通后：记录来源、负责角色和客户主动表达的需求，设下一步待办。
- 后续一至两天内：如确有相关价值且适合联系，发送一次资料或服务提醒；客户已在沟通中则不另跑定时消息。
- 未回复：按照约定或试点频率收尾，不因“新客必须 48 小时转化”连续轰炸。

承诺“五分钟回复”之前，检查营业时间与值班安排；离线欢迎信息明确何时有人响应。主动营销不得伪装成紧急服务通知。

## 自动化蓝图的关键规则

每条规则需包含：事件、时间、对象筛选、排除条件、动作、负责人、去重键、执行结果、取消事件和异常处理。给真实可用的连接方式，不默认所有工具都有 API。

示例规则卡：

```text
规则：补货提醒候选
触发：订单系统中的有效订单达到该商品的预计补货检查日
入选：可确定客户与订单关联；营销联系范围明确；无未解决售后
发送前复查：无新有效订单；无进行中的人工沟通；未超总触达预算
动作：生成给负责顾问的待办及候选话术
去重：客户 ID + 原订单 ID + 规则版本 + 本轮周期
取消：客户复购、拒绝、退订、出现投诉或人工标记暂停
异常：数据缺失进入人工核对；失败按可确认状态处理，不盲目重发
完成证据：分别记录待办创建、顾问处理与可获得的发送结果
```

规则卡是设计稿，未连接系统时不能称为已自动化。正式执行还受工具权限、用户授权与平台确认步骤约束。

### 触达冲突与优先级

一个客户共用一份活动与触达记录，包含最近联系、所属流程、下一步、取消原因和负责角色。优先处理客户主动请求、履约与问题，其次才是营销。

发送前重读状态，避免名单筛选后客户已下单仍收到“还没买吗”。人工作出新承诺或接管对话后，暂停原营销序列，由负责人明确何时恢复。退订与投诉变更应优先于定时触发。

不同员工、社群和活动叠加的频次按客户累计；不能以每条流程各自“合规”推导总体验合理。投诉增加或数据失真时先暂停扩量。

### 身份、权限与交接

客户 ID、企微外部联系标识和小程序身份的关联，需要实际具备合法获取路径和可验证映射；同名同头像不能当同一人。没有匹配能力时用受控人工核对，不声称已有统一画像。

会话记录、标签批量更新、离职继承或客户转接，遵循企业现有权限和实际授权。准备交接清单可以直接做；执行转接或导出前核对范围。不要把工具品牌、付费 SCRM 或定制小程序设为默认依赖。

## 团队运行与落地

按现有人力安排周节奏，计入内容准备、回复、服务、记录和复盘的总工时。先跑入口承接和交付，再补培育、复购与扩量；用户已有成熟流程时直接修瓶颈。

培训材料包含来源对应欢迎语、常见问题与异议、资料位置、异常升级和交接示例。检查执行完成证据，不能只考核发了多少消息。

上线前应能回答：谁接手、何时执行、如何去重、客户回复后如何停、数据失效怎么办、如何知道任务实际完成。未确认项标注负责人和核验动作，不反复要求用户批准已经授权的准备工作。
