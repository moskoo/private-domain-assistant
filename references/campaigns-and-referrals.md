# 私域活动、直播与转介绍

用于活动方案、直播物料、老带新与伙伴推荐。先确认可兑现权益与经济账，再安排传播与触达。

## 通用活动卡

记录目标人群、要促成的行为、产品与资格、活动日期和时区、真实价格、库存或名额、优惠叠加条件、退款规则、履约容量、总预算、负责角色和入口。未知项标为待确认，不写进面向客户的确定性承诺。

预算至少包括折扣、赠品采购与配送、渠道费用、奖励和执行人工，按业务补充其他成本。用同一收入口径计算，折扣已体现在净收入时不能再次扣除。

客户参与规则应易懂：谁能参加、怎样完成、能得到什么、何时得到、有哪些限制、如何咨询。不以假库存、假倒计时、虚构原价或冒充客户聊天制造紧迫。

## 私域直播

先确认直播的实际日期时间、主题、目标客群、入口、已确认权益、现有阵地、人力和可取得的观看/交易数据。

### 三阶段物料

| 阶段 | 目标 | 可交付材料 |
|---|---|---|
| 预热 | 让适用客户知道来能解决什么 | 主题介绍、问题征集、演示片段、真实福利与预约入口 |
| 开播提醒 | 帮已感兴趣者找到入口 | 简短提醒、时间与入口、一个行动 |
| 播后承接 | 回答未解决问题并完成服务 | 回顾、相关问答、咨询邀请、订单与履约确认 |

用户要整套物料时，为每条给日期时间、渠道、对象、原句、配图或素材、责任角色。把群、朋友圈和私聊排在同一张触达表；不要把每个倒计时节点都再私聊一遍。

为整场活动设定主动联系节点与最大无回应次数，综合客户偏好、是否预约、其他活动占用和实际平台限制。没有基线时先做低频试点；取消不必要的提醒，客户回复或购买后及时分流。不要把某个固定次数当作所有业务的通用规则。

### 播后分流

- 可确认未观看：给有独立价值的回顾，不能用“我知道你错过了”虚构监测。
- 可确认观看但未下单：结合用户真正提出的问题答疑，不能把观看等同于购买意愿。
- 已下单：转入确认与服务，不继续催付同一产品。
- 无法识别观看者：发一般回顾或让客户自愿选需求，不伪造“观看未购”名单。
- 投诉、退订、无需求：排除营销序列。

复盘区分唯一预约人数、唯一到场人数、全部观看者、下单人数、有效订单与退款。只有能匹配预约和到场身份时，才计算“预约到场率”；不同渠道的总人数不能简单相加当去重触达。

## 客户推荐与伙伴推广

客户推荐以真实满意与关系为基础；伙伴推广涉及约定的佣金、素材使用和结算，两者不要混用资格与统计分母。

设计推荐闭环：恰当邀请时机 → 容易完成的分享 → 新客户自愿进入并获得价值 → 资格确认与奖励兑现 → 效果记录。

### 触发与分享

在服务完成、问题解决、客户表达满意或价值被验证后，判断是否适合提出一次推荐邀请。注册、加好友或付款本身不证明满意。

给客户可编辑的简短分享稿和真实用途说明；可用其口吻起草，但不能编造体验或让经营者假扮客户发布。被推荐人应主动进入或同意介绍，不导出通讯录代发。

### 机制规格

| 项目 | 需明确的内容 |
|---|---|
| 推荐资格 | 哪些客户或伙伴可参加，既有客户是否计入 |
| 成功事件 | 有效咨询、首次付费或履约完成等，选一个明确口径 |
| 奖励 | 给谁、给什么、成本、单人上限和总预算 |
| 归因 | 专属标识或可核验记录、有效窗口、多推荐人冲突规则 |
| 状态 | 已邀请、资格待确认、已有效、已发奖、取消 |
| 取消与异常 | 退款、自荐、重复、虚假订单、未履约如何处理 |
| 通知与结算 | 何时告知进展、何时发放、由谁确认和处理争议 |

先确认资格可以及时通知，正式发奖按已公开的成功条件和退款窗口执行；不能一边规定履约后奖励，一边注册即付款。

单边或双边奖励根据客户动机、参与摩擦与实际利润比较，通过小范围测试决定。奖励预算看可承受的新增客户成本和贡献，不凭未知终身价值预支高佣金。

### 小范围经济账

对几个可执行选项比较：参与人数、独立有效新客、有效订单、净收入、贡献、全部成本和预算峰值。没有历史数据时给假设范围与保守情景，不能把 1 传 5 的数学过程当实际增长预测。

K 系数只描述规定周期和口径下的推荐传播，不证明长期可持续；检测无效参与和重复客户，不能为拉高分享次数设置刷屏、强制转发或多级拉人头奖励。

伙伴方案还需明确授权范围、审核素材、追踪标识、佣金口径、退款冲回、结算周期和退出规则。准备草案无需联系伙伴，实际招募消息和付款须有相应授权。

## 交付前核对

宣传、客服答复、落地入口和结算规则是否一致；总预算与最大可能发奖额是否可承受；活动是否挤占正常服务；购买或拒绝能否及时停止营销；不具备的数据是否明确标为未知。
