<h1 align="center">私域运营助理</h1>

<p align="center">Private Domain Assistant · 面向微信与企业微信的运营 Agent Skill</p>

把业务资料、客户记录和运营数据，转成能执行的方案、能使用的内容、能跟进的话术与能复盘的指标。

适用于个人经营者、门店、品牌私域团队、企业微信运营和知识服务社群。既可以处理“一条客户回复”，也可以搭建“从获客到复购的完整流程”。

**能力概览：** 经营诊断 · 获客承接 · 客户分层 · 朋友圈 · 社群 · 私聊转化 · 企微 SOP · 复购唤醒 · 私域直播 · 转介绍 · 数据复盘。

**交付形式：** 标准 Agent Skills 文件包，按场景加载操作说明。技能本身无需 Python 或额外的 API Key，也不绑定某一家 SCRM；宿主 Agent 的登录、模型配置和使用费用按所选产品要求处理。

## 快速开始

1. 下载并解压完整技能包，找到同时包含 `SKILL.md` 和本文件的目录。
2. 选择下方一种安装方式，将**整个技能目录**放到你的 Agent 技能位置。
3. 在 Agent 中重新加载技能或打开新会话，提供业务背景并开始提问。

有 Node.js 18 或更高版本时，可在本目录执行：

```bash
node scripts/install.mjs --agent codex --scope user
```

将 `codex` 替换为 `claude-code`、`cursor`、`github-copilot`、`gemini-cli` 或 `opencode`，即可安装到相应工具的用户技能位置。没有 Node.js 时，使用[手动安装](#手动安装)。

第一次可直接提出：

```text
请使用 private-domain-assistant。

我经营一家社区烘焙店，客单价约 60 元，通常每周复购。
目前有 800 位微信好友、2 个顾客群，由店长每天花 30 分钟维护。
我想先改善新客加好友后无人承接的问题。
请给我一份两周执行方案，包含欢迎回复、最小客户标签、每日动作和复盘指标。
没有提供的经营数据请标为待确认，不要替我编造。
```

以上为演示业务背景，实际使用时替换为自己的信息。

## 能力与交付物

| 场景 | 适合的问题 | 典型交付物 |
|---|---|---|
| 经营诊断 | 私域增长停滞、团队执行困难、投入难判断 | 瓶颈与证据、优先动作、负责人和试点计划 |
| 获客承接 | 门店、内容、直播等入口来客后没有下一步 | 入口价值、来源记录、欢迎回复和交接流程 |
| 客户分层 | 好友很多，分不清需求和当前进度 | 最小档案、标签字典、分层规则和对应动作 |
| 朋友圈 | 不知道写什么、内容像硬广、素材不足 | 选题、配比、7/30 天日历、成稿与配图建议 |
| 社群 | 建群后冷场、管理员忙、群的价值不清楚 | 建群判断、欢迎群规、启动和激活排期 |
| 私聊转化 | 不会破冰、客户问价、报价后沉默 | 当前回复、需求问题、异议分支和下一步 |
| 企微 SOP | 员工各自发挥、客户交接与定时任务混乱 | 状态、触发、排除条件、素材、责任和取消规则 |
| 复购与唤醒 | 不知道何时联系老客，唤醒只能发券 | 周期判断、优先名单、触达与服务方案 |
| 私域直播 | 预热临时写，播后没有承接 | 预热、提醒、回顾、按已知状态分流的物料 |
| 转介绍 | 老带新规则复杂，奖励与成本不好控制 | 邀请时机、分享稿、有效事件、归因和奖励规则 |
| 数据复盘 | 指标口径混乱，销售额和利润混算 | 漏斗、口径、成本计算、实验和调整条件 |

方案会匹配人力、品类周期和可兑现权益。用户只要一句话时，输出聚焦当下；用户要完整手册时，再展开相关环节。

## 安装指南

### 包结构与兼容方式

本项目遵循 [Agent Skills 标准](https://agentskills.io/specification)：技能目录名与 frontmatter 的 `name` 均为 `private-domain-assistant`，入口固定为 `SKILL.md`，所有操作说明与图片使用相对路径。

`agents/openai.yaml` 提供 Codex 的显示名称、默认提示词和图标；核心工作流程保存在通用 `SKILL.md` 中，其他工具可使用相同的技能包。

下表列出各工具的本地技能目录。将整个 `private-domain-assistant/` 放入所选目录，即形成 `…/private-domain-assistant/SKILL.md`。

| Agent | 当前项目的技能目录 | 当前用户的技能目录 |
|---|---|---|
| [Codex](https://learn.chatgpt.com/docs/build-skills) | `.agents/skills/` | `~/.agents/skills/` |
| [Claude Code](https://code.claude.com/docs/en/skills) | `.claude/skills/` | `~/.claude/skills/` |
| [Cursor](https://cursor.com/docs/skills) | `.cursor/skills/` | `~/.cursor/skills/` |
| [GitHub Copilot](https://docs.github.com/en/copilot/concepts/customizations/agent-skills) | `.github/skills/` | `~/.copilot/skills/` |
| [Gemini CLI](https://geminicli.com/docs/cli/using-agent-skills/) | `.gemini/skills/` | `~/.gemini/skills/` |
| [OpenCode](https://opencode.ai/docs/skills) | `.opencode/skills/` | `~/.config/opencode/skills/` |

`~` 表示当前用户主目录；Windows 通常为 `C:\Users\你的用户名`。项目安装从对应业务工作区使用，用户安装可供该用户的多个项目使用。

Codex、Cursor、Copilot、Gemini CLI 和 OpenCode 的当前文档也支持 `.agents/skills/` 共享位置。多个工具共用工作区时，可优先保留这一份，避免再复制同名版本到它们的其他扫描位置；Claude Code 使用自己的 `.claude/skills/`。具体发现顺序和云端范围以各工具的实际版本与运行环境为准。

### 本地安装器

安装器只使用 Node.js 内置模块，支持 Windows、macOS 和 Linux；不联网、不安装 npm 依赖、不改 Agent 全局配置。

用户级安装：

```bash
node scripts/install.mjs --agent claude-code --scope user
```

项目级安装：在**目标业务工作区**执行，并将下面的技能包路径替换为实际路径：

```bash
node "/path/to/private-domain-assistant/scripts/install.mjs" --agent codex --scope project
```

也可以显式指定目标项目：

```bash
node scripts/install.mjs --agent cursor --scope project --project "/path/to/business-workspace"
```

安装前查看计划：

```bash
node scripts/install.mjs --agent github-copilot --scope user --dry-run
```

参数说明：

| 参数 | 用途 |
|---|---|
| `--agent` | 必填，取上表对应标识：`codex`、`claude-code`、`cursor`、`github-copilot`、`gemini-cli`、`opencode` |
| `--scope` | `project` 或 `user`；默认 `project` |
| `--project` | 已存在的目标项目目录；仅项目级有效，默认当前目录 |
| `--dry-run` | 仅输出计划，不复制文件 |
| `--help` | 查看帮助 |

安装器只复制本项目的技能文件、说明、许可证、操作参考、图片和安装脚本，不复制 `.git`、业务资料或工作区中的其他文件。

已有同名目录时会停止，保护你的定制内容。更新前先把旧目录备份到**技能扫描范围之外**，再安装新版本，并手动合并自己的修改。不要把包含 `SKILL.md` 的备份放在同一个 skills 目录下，以免被再次发现。

### 手动安装

适合没有 Node.js、离线安装或自定义 Agent 路径的情况。

1. 在表格中选择项目或用户范围。
2. 创建对应的技能目录。
3. 将完整 `private-domain-assistant/` 文件夹复制进去。
4. 确认入口是 `技能目录/private-domain-assistant/SKILL.md`，且 `references/` 与 `assets/` 都在。

以用户级 Claude Code 为例，正确层级是：

```text
~/.claude/skills/
└── private-domain-assistant/
    ├── SKILL.md
    ├── README.md
    ├── references/
    ├── assets/
    ├── agents/
    ├── scripts/
    └── LICENSE
```

不要只复制 `SKILL.md`，也不要多嵌套一层 `private-domain-assistant/private-domain-assistant/`。使用其他支持 Agent Skills 的工具时，同样保留整个目录，放入该工具认可的技能位置。

### 使用 skills CLI

已使用 [skills CLI](https://github.com/vercel-labs/skills/blob/main/docs/commands.md) 管理技能的用户，也可在本项目根目录执行：

```bash
npx skills add . --skill private-domain-assistant --agent codex --global --copy
```

替换 `--agent` 选择其他工具。去掉 `--global` 可按该 CLI 的项目范围安装；此时请从目标项目调用技能包的本地路径，例如 `npx skills add /path/to/private-domain-assistant ...`。`npx` 首次运行需要取得 CLI 包；离线场景选择本地安装器或手动复制。

这里只提供本地包安装命令。仓库发布后，可将 `.` 替换为真实仓库地址，无需虚构 GitHub 用户名或依赖某个固定仓库名。

## 提供业务信息

把下面模板按需填入对话。局部任务只填写有关部分，未知数据直接写“未统计”。

```text
【业务】卖什么；目标客户；客单价；毛利或可承受成本；决策/复购周期
【现状】获客入口；好友与群规模；目前怎样运营；已有素材与工具
【目标】这次希望改变什么；当前基线；希望检查效果的时间
【资源】负责角色；每天/每周可用时间；预算；已确认可兑现的权益
【材料】客户原话、匿名订单、聊天摘要、现有内容或报表
【触达】客户偏好；已联系记录；不可联系或需要暂停的对象
【交付】方案/话术/日历/SOP/复盘；周期；格式；需要几套或多少条
```

首次搭建提供业务、资源和主目标即可。不要为了“资料完整”先做一大轮填表；资料足够时，技能会直接产出，缺口只在会影响判断的地方补问。

## 使用示例

以下示例均可复制并替换业务信息。不同 Agent 的 `$`、`/` 或技能选择方式按上表使用。

### 1. 私域诊断与起步

```text
使用 private-domain-assistant。
我们做家居定制，有 2 家门店、3 位顾问、约 2000 位企微客户。
目前各人自行发朋友圈，没统一记录下一步，成交周期约 1–3 个月。
请先找最值得修的三个环节，再给四周试点安排。
要求不新增人手，每个动作有负责人、完成证据和复盘口径。
```

### 2. 30 天朋友圈日历

```text
使用 private-domain-assistant。
我是做社区烘焙的店长，表达风格亲切直接，可以拍制作过程，暂无客户评价授权。
请安排从我指定日期起连续 30 天的朋友圈日历，标出休息和素材采集日。
给每条的主题、开头、配图、行动引导与准备时间；先为第一周写完整成稿。
没有评价素材的栏目请用真实产品演示代替。
```

### 3. 社群冷场诊断

```text
使用 private-domain-assistant。
这是一个 150 人的产品使用交流群，最近两周几乎只有管理员发活动。
以下是最近五条内容和曾经有回应的话题：[粘贴匿名内容]。
请依据这些材料诊断冷场原因，设计 14 天低成本激活计划。
每天运营不超过 25 分钟，给能直接发的问题和管理员接话方式。
请说明到期后怎样决定继续、降频或结束。
```

### 4. 一条客户回复

```text
使用 private-domain-assistant。
客户原话：“你们这个 699 元套餐比别家贵在哪？”
套餐实际包含：[填写真实配置、服务和限制]。
我们此前沟通：[贴必要上下文]。
请给一条简短回复，直接回答比较点，再问一个必要问题。
不要编造对方产品缺点或额外优惠。
```

### 5. 标签与客户分层

```text
使用 private-domain-assistant。
附件是已匿名的客户记录，包含来源、最近沟通、购买和售后状态。
请先检查哪些字段能可靠使用，再设计最小标签字典和分层行动表。
将购买阶段、客户价值和触达许可分开，不要把没有记录当作没有购买。
给出一周内按现有人力能完成的补标计划。
```

### 6. 复购与唤醒

```text
使用 private-domain-assistant。
我们卖日用消耗品，通常 45 天左右补货。
以下是匿名订单与客户状态：[粘贴或附文件]。
本次可用权益为：[真实权益及成本上限]。
请列出适合补货提醒、需要服务、暂不联系和数据待核实的对象。
```

### 7. 企业微信全链路 SOP

```text

```

### 8. 私域直播与播后承接

```text
直播主题、实际时间和权益：[填写]。
私域阵地与可用人力：[填写]。
请给预热、开播提醒和播后承接物料，统一安排各渠道的触达节点。
```

### 9. 老客转介绍

```text

我们提供宠物洗护，希望满意老客自愿介绍新客户。
首单实际价格、变动成本、可用奖励、总预算：[填写]。
```

### 10. 经营数据复盘

```text
使用 private-domain-assistant。
附件是本月的渠道、联系、订单、退款与成本记录。
请先检查去重、批次、观察窗口和可比性，再分析最主要的流失环节。
分别列出净收入、营销前贡献和活动观察回报；没有对照时不要声称增量 ROI。
最后只给下一周期最值得验证的两个改动及停止条件。
```

## 日常使用流程

1. **建一份业务简报。** 保存稳定的产品、客群、周期、资源和服务约束，后续任务直接引用。
2. **选择本次目标。** 例如先修接待，再安排内容；每次让一个环节有清楚的进展。
3. **生成可执行产物。** 排期、成稿、标签或 SOP 应能落到负责角色与完成标准。
4. **按真实情况执行。** 人工确认业务事实与适用对象；外部动作由已有工具和授权完成。
5. **带数据回来复盘。** 附上实际结果和执行偏差，让技能决定继续、修改或停止。

持续运营需要保存自己的业务简报和复盘记录。本技能不会自动建立跨会话客户库；跨会话记忆取决于宿主与用户提供的文件。

## 数据与执行说明

### 客户数据

分析优先使用匿名 ID 与必要字段。贴聊天记录时去掉手机号、地址和无关个人信息；业务上确实需要的字段由你决定提供范围。

本技能本身是本地文本和图片文件，不包含上传客户资料的后台或网络脚本。实际数据如何处理，取决于你使用的 Agent、模型、连接器和账户设置。

### 文件与工具

读取 Excel、导出文档、联网核验等能力由宿主提供。有相应工具时可按任务使用；缺少工具时，技能会提供可复制的表格或正文，并说明哪些部分尚未完成。

企微接口、发送任务、观看名单和身份关联等能力需要真实可用的数据路径。配置蓝图会标出人工部分和待核验项，不将“创建任务”直接当作“客户收到消息”。

### 外部执行

本包没有企微发送机器人或内置客户连接器。需要发送消息、拉群、修改标签、发券或付款时，宿主必须具备相应工具和授权；撰写成稿可以独立完成。

### 判断原则

- 客户拒绝本次产品与退订全部营销分别处理；退群本身不推断为全渠道退订，也不作为追问或拉回的理由。
- 复购与沉睡按实际业务周期判断；家具等长周期业务可以侧重服务、配套与推荐。
- 跟进频率随客户约定、实际响应与平台限制调整，不固定照抄两次、三次或某个日程。
- 案例、库存、价格、资质、效果与优惠必须有真实依据。
- 订单、客户、退款和成本口径先统一；净收入、贡献和增量效果分别计算。

## 常见问题

**安装后看不到技能？**

检查是否用的是支持 Agent Skills 的版本与会话模式；确认 `SKILL.md` 的大小写、目录层级、技能名和资源是否完整；检查工作区信任和技能启用状态。重新加载技能或开新会话；不要只看某次回答是否“像用了技能”。

**为什么更新后仍像旧版本？**

检查项目级与用户级是否存在同名副本，以及共享目录与工具专用目录是否重复。将备份移出扫描范围，保留你希望生效的版本后再加载。

**可以直接上传 ZIP 到任意 AI 产品吗？**

ZIP 是分发包。支持文件技能导入的产品可使用其导入流程；文件夹发现型工具按本指南解压并安装。普通聊天应用可手动提供 `SKILL.md` 与任务相关操作说明，但完整的自动发现和按需加载由该应用决定。

**能自动发朋友圈、群发和维护客户吗？**

可以生成内容、排期、规则与操作材料。自动执行依赖宿主工具、账户权限和实际授权，本包不自带这些连接能力。

**一定要提供完整客户表、精确毛利或所有标签吗？**

按任务提供即可。写一条回复只需必要上下文；客户分层需要相关记录；算利润或 ROI 才需要相应成本。缺数据时会保留未知项，先完成能判断的部分。

**为什么我的客户没有被标为沉睡？**

只凭一段时间没下单不够。长周期商品、未购线索、数据缺失和正在售后都有不同处理方式，技能会解释判断依据。

**本地安装会同步到云端 Agent 吗？**

本地目录安装只保证文件位于当前机器。云端会话、远程工作区和团队共享的发现范围由宿主决定，需要按该产品的仓库或团队分发机制配置。

**如何卸载？**

通过本地安装器或手动复制安装的版本，先查看安装计划或上表确定精确路径，再移走对应的 `private-domain-assistant/`。通过 skills CLI 安装的版本使用该 CLI 的移除流程。不要删除整个 skills 目录。

## 参与改进与许可证

欢迎通过 Issue 或 Pull Request 提供具体改进。请写明业务场景、匿名输入、实际输出、期望行为和宿主工具；优先修复可复现问题，避免只增加通用提醒。不要提交真实客户记录、访问凭据或未经授权的截图。

修改后检查：技能名与目录一致、相对链接有效、安装器 `--dry-run` 输出正确，以及至少一个真实场景能得到与请求规模相称的产物。变更安装器时还应验证不覆盖已有目录。
